# Physical acceptance: ESP32-S3 OLED kit — 12 October 2026

The owner ran this test on their own kit, at their desk, on a Mac. The owner observed
each physical result. The gateway request log (`serve --request-log`) recorded each
command. This record covers this one kit. It does not prove that every board works.

## Hardware as inspected

| Part | Observed |
| --- | --- |
| Board | DevKitC-style board. The module is marked `ESP32-S3-N16R8` (`WROOM-1` is not printed). Two USB-C ports: **USB** (native) and **COM** (WCH CH343 bridge). |
| Chip | ESP32-S3 revision v0.2, MAC `84:c7:bb:57:14:8c`, 16 MB quad flash (read with esptool). PSRAM was not checked. |
| Display | 0.96-inch 128×64 module marked `RG1.30 IIC V2.2`. Pins left to right: VCC, GND, SCK, SDA. I²C address `0x3c`. The controller behaves as an **SH1106**: an SSD1306 driver left a lit column at the right edge. |
| Wiring | VCC → 3V3, GND → GND, SCK → GPIO9, SDA → GPIO8. Female jumpers on the board's header pins, no breadboard. |
| Light and button | Onboard RGB pixel on GPIO48; BOOT button (GPIO0), read after boot. |
| Host | macOS 27.0; gateway v0.1.0-alpha.5 (`dev` `8b4380e`); board on `/dev/cu.usbmodem*` through the **USB** port. |

## Firmware

`examples/oled-kit/main.cpp`, environment `esp32s3-oled-kit` (16 MB flash, octal PSRAM
memory type, native USB CDC). Final tested image: SH1106 build of commit `5517dc0`.
The factory flash (first 2 MB and the partition table) was backed up privately before the
first write. Each write was verified by esptool's flash hash check.

## Grok Bot

In a new chat in the owner's Grok Bot desktop app on this Mac, the message asked Grok Bot
to run `grok-gadgets-gateway rehearse --device oledkit-84c7bb57148c --command display.text --args '{"text":"Hi from my Grok Bot"}'`.
The message was sent at 14:29:27 IST. **No approval card appeared**: the account's
Execution on Local Computer setting was still **Always allow** from the 12 October
local-execution test, so the command ran without a per-command approval.
The gateway log recorded `gadgets_list_devices`, `gadgets_command display.text`
(`executed`, `simulated: false`) and `gadgets_get_state` at 08:59:41 UTC (14:29:41 IST).
The chat showed the command output, ending in `Rehearsal passed`, at 14:29:53 IST.
The owner saw "Hi from my Grok Bot" on the OLED.

This is the documented local route (a shell command on the Mac, outcome (b) of the hub's
ADR 004). Grok Bot did not call the MCP tools itself. The log's client name is
`grok-gadgets-rehearse`; the link to Grok Bot is the chat and the matching time.
The approval step was not exercised in this test.

## Problems found and fixed

- **Display start-up hung.** Passing the I²C pins to the U8x8 constructor made `begin()` hang.
  The firmware now starts the display on the Wire bus it already opened.
- **Wrong controller default.** The module is an SH1106. SH1106 is now the default;
  `-DOLED_KIT_SSD1306` selects the other controller.
- **Swapped data wires.** The firmware now also finds the display with SDA and SCL swapped,
  and reports the pins and address in its state.
- **Unstable USB at first.** The board restarted several times when the cable or jumpers
  moved. After the jumpers moved from the breadboard to the header pins and the board lay
  flat, the connection stayed stable. The exact cause was not isolated.
